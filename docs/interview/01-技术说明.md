# EdgeVision：RK3568 视频感知与事件录像系统
版本日期：2026-09-12。定位：Linux 音视频 / 边缘 AI 应用开发个人项目。
本文对应本次 Git 提交的项目代码；交付索引记录提交号。板端工程目录为 /root/workspace/EdgeVision-Agent。

## 1. 项目要解决什么问题
将摄像头采集、人员检测、实时预览、事件留存和远程控制组成可运行系统。核心需求不是每帧都检测，而是在推理速度低于输入速度时仍保持视频连续、检测结果新鲜，并让异常和录像结果可查询。

已形成的功能路径：
摄像头 → 原始帧 → NPU 人员检测 → ROI / 连续帧确认 → 事件录像 → 文件与 JSON 清单 → 控制接口查询。
同时提供原始视频 RTSP 预览和异步 JPEG 抓拍。当前预览没有叠加检测框。

## 2. 数据路径与线程
~~~text
V4L2 采集 → 固定容量帧池（packed YUYV，只读共享）
             ├→ 有界推理队列 → 最新帧 → CPU/RGA 前处理 → RKNN → YOLOv5 后处理
             │                                              ├→ 最新结果查询
             │                                              └→ ROI 事件触发
             ├→ 有界视频队列 → YUYV 转 NV12 → MPP H.264
             │                                   ├→ RTSP
             │                                   └→ 录像队列 → GOP 预录缓存 → 文件/清单
             └→ 最近帧引用 → 有界 JPEG 任务队列 → 磁盘 → 异步响应

TCP / epoll → 查询、启停推理、阈值修改、抓拍、录像、重开摄像头
eventfd → 跨线程完成通知；timerfd → 定时输出 metrics
~~~
显式工作线程包含采集、推理、视频投递、录像、JPEG、网络和 GLib RTSP。第三方库还可能创建线程，不能描述成“系统只有三个线程”。

采集线程不等待推理完成。推理线程独占 RKNN 上下文，控制线程只修改状态、投递任务。JPEG 写盘与网络控制分离；完成后向 EventLoop 投递回调。

## 3. 采集与内存生命周期
V4L2Camera 负责用户态设备配置、缓冲映射、poll、DQBUF/QBUF 和恢复。检查协商尺寸、stride、bytesused，将有效图像行复制到自有帧池后立即归还驱动缓冲，避免下游持有驱动缓冲太久。

FramePool 预分配像素存储；shared_ptr<const Frame> 发布只读引用，最后一个消费者释放后归还。池 State 被释放器持有，避免池对象先销毁后悬空访问。帧带有序号、采集完成时间和推理代际号。

这里仍存在 V4L2 到帧池的复制、颜色转换及第三方分配。准确表述是“固定容量像素帧池与跨线程只读引用共享”，不是 DMA-BUF 全链路零拷贝，也不是全系统零分配。

## 4. 队列和背压
| 分支 | 饱和时策略 | 原因 |
| --- | --- | --- |
| 推理 | 入队满时丢旧帧，消费时取最新并清掉旧帧 | 优先结果时效 |
| 视频投递 | 有界队列，满时丢旧帧 | 限制积压 |
| JPEG | 队列满返回拒绝 | 不静默接受无法完成的控制任务 |
| 录像 | 包队列满标记缺口，收尾并等待关键帧重新建立缓存 | 防止把不连续码流当作完整录像 |
| RTSP appsrc | 超过缓冲预算后丢弃并等待关键帧 | 限制单路径积压 |

有界队列约束应用层内存与等待，不等于第三方库和操作系统所有缓冲均有硬截止保证。视频队列和 RTSP 丢包口径也需分别看，video_dropped=0 不代表全网络零丢包。

## 5. 模型部署与正确性
模型为 YOLOv5，输入 640×640，匹配三个 NCHW 输出头。源图 640×480 经 Letterbox，后处理使用同一几何信息还原坐标，完成 anchor 解码、阈值过滤和同类别 NMS。

当前模型输出为 logits，默认 output_activation=logits。运行时检查输入输出布局与支持的数据类型。native_outputs=true 对 affine INT8/UINT8 原生输出按需反量化，避免 SDK 将整个输出张量展开为 float；不支持的类型回退浮点路径。

固定人员帧上交替运行浮点/原生输出，预热 2 轮、统计 10 轮，检测类别、框和置信度一致。单帧对照不等于全数据集 mAP 验证。

RGA 为可选同步预处理路径，当前通过虚拟地址包装，尚未打通 DMA-BUF。实测当前输入下 CPU 更快，因此保留 CPU 默认。

## 6. 视频和事件
视频链：GStreamer appsrc(YUY2) → videoconvert(NV12) → mpph264enc → h264parse → appsink。
使用厂商 MPP 插件执行硬件编码，不是自己实现 H.264 编码算法。

人员框中心进入归一化 ROI，连续 event_confirm 次确认后触发；后续触发延长尾随时间。这是简单事件规则，没有目标跟踪 ID。
预录缓存按 GOP 保留；起点必须包含可解码关键帧，实际前录可能多保留一个 GOP。

事件输出为 Annex-B H.264 裸流和 JSON 清单。get_events 提供当前状态及最近 32 条结束记录，记录 event_id、路径、起止时间、结束原因及写入状态。重叠触发会合并，事件 ID 在打开文件时生成，不是每个请求都有独立录像 ID。

无编码包 2 秒时，录像线程自主收尾为 input_timeout / complete=false。摄像头重启设置时间边界、清空旧预录缓存，旧会话编码包不用于新事件。记录写入成功与业务完整是不同概念：不完整录像也可能成功保存供追溯。

## 7. 慢推理与故障处理
默认单帧服务耗时 >=150 ms 连续 3 次进入 degraded；每次结束后冷却 200 ms。连续 10 次低于 112.5 ms 才恢复。服务耗时包含前处理、RKNN、输出及后处理，不包含排队。

输入/结果有效期为 500 ms，超龄结果不发布、不触发事件。get_detections 的 fresh 指示结果是否有效。活跃处理超过 2000 ms 时，查询报告 stalled；这是观测状态，不表示已经终止任务。active_ms 是整次任务时间，不能单独定位到 rknn_run。

摄像头连续失败后关闭重开，缺失时按间隔重试。stop/start 和摄像头重启通过代际号隔离旧推理结果。连续 3 次推理异常暂停推理；start 只重开推理开关，不销毁重建 RKNN。编码器错误标记 unhealthy，尚未自动重建。

真实 RKNN 或磁盘调用永久阻塞时，当前进程不能保证限时 join。下一步应把推理放进子进程，增加父进程监控、超时回收、重启退避、共享缓冲所有权和代际隔离。

## 8. 测量结果与口径
### 固定输入优化对照
同一 640×480 YUYV 帧、30 Hz 回放、真实 NPU/MPP、Release、视频开启，各组 60 秒。
| 路径 | 检测 FPS | 编码 FPS | 采集完成至检测完成 P95 |
| --- | ---: | ---: | ---: |
| CPU + SDK 浮点输出 | 11.74 | 29.99 | 157.68 ms |
| CPU + 原生量化输出 | 14.59 | 29.99 | 135.19 ms |
| RGA + 原生量化输出 | 14.27 | 29.99 | 138.01 ms |

单轮同输入对照：原生输出检测吞吐提升约 24.3%，检测链 P95 降低约 14.3%。这不是 NPU 本体提速，也不是多轮统计结论。该对照发生在最新帧消费优化之前，不与后面的实采日志直接算增益。

### 最新用户实采日志
运行约 116～126 秒的三个快照：采集约 19.99 FPS，编码约 20 FPS，处理约 14.39 FPS；最后快照检测延迟平均 93.50 ms、P95 118.60 ms，队列等待平均 24.95 ms；NPU 平均 51.48 ms，完整处理平均 68.54 ms；RSS 约 54 MB。健康 normal，无持续采集超时增量。

这是短窗口观察，未证明 24 小时稳定性。capture_wait_and_copy 约 50 ms 包含等帧，不能写成拷贝耗时。CPU 约 77%～80% 按单核 100% 统计。stages_ms 保留最近 1024 个样本，连续快照大量重叠。检测延迟起点为自有帧采集完成，未包含曝光、网络和播放器缓冲。

### 验收
基础 CTest 通过；首轮功能验收 11 项通过；新增慢推理验收 8 项通过。覆盖协议、异步半关闭抓拍、设备路径缺失/恢复、RTSP 解码/重连、录像解码、慢推理视频独立性、延迟撤销恢复及摄像头重启录像隔离。
600/1500 ms 延迟注入发生在 RKNN 返回之后，验证策略，不等价于真实 NPU 驱动卡死。

## 9. 复现与代码导航
在板端项目根目录：
~~~sh
cmake -S . -B build-refactor -DCMAKE_BUILD_TYPE=Release
cmake --build build-refactor -j2
(cd build-refactor && ctest --output-on-failure)
./build-refactor/edge_agent configs/default.json
~~~
控制示例：
~~~sh
python3 tools/edge_client.py get_status
python3 tools/edge_client.py get_metrics
python3 tools/edge_client.py get_detections
python3 tools/edge_client.py capture
python3 tools/edge_client.py record_event
~~~
